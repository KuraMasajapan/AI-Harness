# Curiosity-First Recombination Principle

## Signal

A recurring design instinct in AI-HARNESS is not:

> "This is accepted as correct, therefore implement it."

It is closer to:

> "This looks interesting. What happens if these existing pieces are combined differently?"

Many important products and systems are not created from entirely new primitive technologies. Their value can come from recombination, timing, integration, usability, and a new framing of what existing components are for.

## Proposal

Preserve a **Curiosity-First Recombination Principle**:

```text
notice ordinary capability
→ ask what else it could become
→ combine with another capability
→ build a small experiment
→ observe actual value
→ keep / reject / refine
```

The trigger is curiosity, not confidence.

Validation comes after the experiment.

## HARNESS relevance

This principle already appears in several directions:

- Obsidian: from note storage to compatibility / relationship graph
- fresh agents: from temporary executors to controllable cognitive viewpoints
- Git / Markdown: from documentation to persistent external memory
- launcher UI: from convenience to system health / family-facing control surface
- public metrics: from logs to optimization evidence
- multi-agent work: from parallel chats to dynamic team composition

## Why this matters

The available world already contains a huge inventory of partially useful mechanisms.

The design advantage may come from:

- seeing an overlooked affordance
- combining components that are usually treated separately
- reducing unnecessary complexity
- testing quickly under real constraints
- keeping only combinations that produce measurable benefit

## Important limits

- novelty of combination should not be confused with technical novelty
- curiosity does not replace evidence
- prior art still matters before public novelty claims
- failed combinations should be retained as lessons where useful

## Why preserve this proposal

A system that continuously explores new combinations of ordinary tools may produce differentiated capability without depending on expensive proprietary infrastructure or original invention at the component level.
