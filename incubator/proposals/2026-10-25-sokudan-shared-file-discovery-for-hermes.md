# SokudanをAI-Harness共通ファイル探索層として活用する案

- 記録日: 2026-10-25
- 判定: **A / CANDIDATE**
- 実装状態: **NOT IMPLEMENTED / Research only**
- 対象: AI-Harness Core、Sokudan、Hermes Local Agent、Codex、BBB
- 起点: Hermesのファイル探索をSokudanで補助できないか、という設計検討

## 提案の要旨
Hermesにファイル探索を全面的に任せるのではなく、**Sokudanがファイル候補の検索・分類を担当し、Hermesが候補の内容を確認して作業する**。SokudanはHermes専用にせず、将来の他エージェントやAI-Harness共通の探索サービスとして再利用する。

## 役割分担
| コンポーネント | 主な責務 |
| --- | --- |
| Sokudan | 索引検索、候補ファイルの絞り込み、文章分類、関連度の補助判定 |
| Hermes | 候補ファイルの読解、作業計画、許可されたツールの実行 |
| Codex | コード修正、テスト、レビュー |
| AI-Harness Access | 実際の読み書き権限の判定。検索結果を権限付与とみなさない |

## 想定フロー
1. 利用者が「BBBのForward Gateに関するファイルを探して」と依頼する。
2. Sokudanが許可された索引を検索し、ファイルパス、見出し、タグ、関連度などの候補を返す。
3. AI-HarnessのAccessルールにより、Hermesが実際に閲覧できる対象を判定する。
4. Hermesが許可された候補の内容を確認し、出典と不明点を示して応答する。
5. コード変更が必要な場合はCodex等の既存開発経路とHuman承認の境界を維持する。

## 実装上の最小構成案（未検証）
- まずはファイル名・パス・Markdown見出し・タグ等の軽量索引と通常の全文検索から開始。
- Sokudanの既存の文章分類機能を候補の分類・順位づけに使えるか検証。
- 意味検索、埋め込み、ベクトルDBは必要性が実証された場合のみ検討する。
- 検索対象は許可済みのディレクトリ／文書に限定し、秘密情報や非公開情報の索引漏洩にも注意する。
- 検索結果には参照元、更新時刻、候補判定の根拠を付け、古い索引や誤判定を検出できるようにする。
- エージェントに直接全ファイル権限を与えず、読み込み・変更・実行を分離する。

## 期待される価値
- Hermesが大量のファイルを毎回総当たりで読む必要を減らせる可能性。
- GPUなし・低メモリの環境でも段階的に検証しやすい。
- Hermesに依存しない共通探索層を作れれば、Codexや将来の家族用AIにも応用可能。
- AI-HarnessのCore / Access分離方針と整合しやすい。

## 制約・未確認事項
- 現在確認されているSokudanの用途は文章分類中心であり、ファイル索引・検索APIは**未実装または未確認**。既存機能で検索できると断定しない。
- 実際の処理速度、精度、メモリ消費、索引更新方法、外部ストレージとの連携は未検証。
- Hermesの導入自体はPhase 0 / NOT IMPLEMENTEDを維持。
- BBBのForward Gateや既存運用には変更しない。

## 次回の検証候補
1. Sokudanの現行API・構成を確認し、既存分類処理を壊さずに探索層を追加できるか評価。
2. 少数のテスト用Markdownで、通常の全文検索とSokudan分類併用の検索精度・速度を比較。
3. 読取許可のないファイルが検索結果や要約から漏れないことを確認。
4. Hermesを使わない状態で検索APIを先に検証し、必要に応じてHermes側から呼び出す。
