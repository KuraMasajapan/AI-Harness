# Grok -> Airtable -> ChatGPT Pilot Run #001

Date: 2026-10-04
Status: END-TO-END HANDOFF PASS / INFORMATION QUALITY GUARDS REQUIRED

## Purpose

Validate the first operational path:

`Grok Automation -> Airtable MCP -> Harness Inbox -> ChatGPT verification -> Human decision`

This pilot tests transport, state isolation, approval boundaries, duplicate protection, downstream verification, and whether an upstream research error can be caught before adoption.

## What was verified

### Transport / handoff
- Grok successfully wrote new candidate records to Airtable through the connected Airtable MCP.
- Airtable received the candidates in `Harness Inbox`.
- ChatGPT independently read the same records through the Airtable connector.

### State / approval boundary
- New Grok submissions used `Status = NEW`.
- `Human Approved` remained false / unset.
- Existing Inbox records were not modified by the unattended run.
- ChatGPT could later change Status and notes during explicit Human-guided review.

### Duplicate / scope behavior
- Grok checked the existing Inbox before submission.
- It reported that no same-URL duplicate existed for the submitted items.
- It submitted only a small shortlist instead of filling a quota.

## Downstream verification finding

ChatGPT review found a material temporal interpretation error in the Codex candidate.

The referenced OpenAI article was published in 2025. Its wording `Starting October 20` referred to 2025-10-20, not a new 2026-10-20 change.

This proved an important boundary:

`Official source != fresh signal`

The source can be authoritative while the observer still misreads the year, relative date, or current applicability.

The Airtable Codex record was corrected to:
- Importance: LOW
- Status: DONE
- Human Approved: false
- Suggested action: IGNORE / DONE
- Correction reason recorded in Summary / Harness Notes

No automatic Core or implementation change occurred.

## Lessons

The pipeline succeeded because the Grok finding was not treated as final truth.

The actual safety path worked as intended:

`Signal -> Structured Inbox -> Independent verification -> Human authority`

Key lesson:
- authority of source,
- freshness,
- temporal interpretation,
- and architectural value

must be evaluated separately.

## Prompt hardening derived from this run

The Grok Automation prompt now requires:

- explicit publication/update-date verification
- absolute date resolution for future changes
- no assumption that an omitted year means the current year
- strict 24-hour observation-window classification
- `Window status: IN_WINDOW / OUT_OF_WINDOW / UNKNOWN`
- no automatic Airtable submission for OUT_OF_WINDOW or UNKNOWN items
- no unattended update or deletion of existing Airtable records
- existing-candidate reinforcement should be reported as an additional Signal instead of creating duplicates
- Human Approved must never be automatically enabled
- Core changes and implementation remain outside the Automation's authority

`External Observer -> Structured Inbox -> Independent AI Review -> Human Decision`

`Grok -> Airtable -> ChatGPT -> Human`
