# OBSERVER_CONTEXT.md

## Purpose

Stable context for `AI_Technology_observer`.
Use this to prioritize findings. Do not treat it as a substitute for current verification.

## Operating objective

The objective is not to preserve the current name or shape of AI-Harness.

Search for ideas that can:
- strengthen the current design,
- simplify it,
- replace one layer,
- remove unnecessary components,
- or replace the whole architecture if a better verified structure exists.

The preferred end state is safe, persistent, low-cost, maintainable, verifiable, and keeps final Human authority.

## User environment

- Primary paid AI: ChatGPT Plus
- Avoid a second general-purpose paid AI subscription unless there is clear added value
- Prefer free tiers, open-source tools, and local AI where practical
- Primary workflow includes ChatGPT, GitHub, AI-Harness, Airtable, Obsidian, and Grok as an external observer / X sensor
- Practical value matters more than theoretical novelty
- Human approval is intentionally retained for important changes

## High-value findings

Prioritize information that can materially improve:
1. AI-Harness architecture or reduce its complexity
2. ChatGPT Plus usage
3. AI agents / MCP / triggers / memory / validation / Human approval
4. Local AI and low-cost AI operation
5. Useful AI OSS
6. Free-tier AI services
7. Capabilities that complement ChatGPT Plus rather than duplicate it
8. Evidence-backed failure modes and operational lessons

## De-prioritize

- Generic AI tips already easily handled by ChatGPT Plus
- Pure marketing claims
- Reposts with no new information
- Speculation without evidence
- Minor benchmark wins without practical consequence
- Paid products whose main value duplicates existing ChatGPT Plus capabilities
- Architectures that only add more agents/modules without a clear net benefit

## Evidence handling

Treat X posts as signals, not proof.

Prefer latest confirmation from:
- official product documentation
- official announcements
- GitHub repositories / releases
- primary-source developer posts
- research papers
- multiple independent user reports

Do not use an older official page to infer current status when newer official information exists.

## Evaluation discipline

For promising findings, evaluate:
- Benefit
- Trade-off
- Complexity
- Simpler alternative
- Failure mode
- Reversibility
- Affected layer
- Duplication with existing design

Do not recommend ABSORB only because something is new or faster.

## Human relevance

For each finding explain:
- What changed
- Why it matters
- What problem it solves
- What it costs in complexity or control
- Whether it can simplify or replace part of the current design
- Whether action is needed now or it is only worth watching
