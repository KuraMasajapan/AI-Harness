# UI UX Pro Max Skill — Design Intelligence Reassessment

## Status

**Stage 1: A+**  
**Stage 2: A**  
**Decision: COMPARISON CANDIDATE**  
**Implementation: HOLD**

Earlier treatment considered UI UX Pro Max primarily as another UI/UX Skill overlapping existing frontend Skills.

The current project has expanded enough that this description is incomplete.

## 1. Officially confirmed current scope

Official repository:

- https://github.com/nextlevelbuilder/ui-ux-pro-max-skill
- MIT license for the open repository
- Claude Code and Codex installation paths are documented

Current official README describes:

- 79 searchable UI styles
- 192 product categories
- 192 color palettes
- 74 font pairings
- 25 chart types
- 22 tech stacks
- 119 UX guidelines
- 192 industry-specific reasoning rules
- Design System Generator
- BM25-backed search / matching
- stack-specific guidance
- Codex / Claude / multiple agent installation options

Current v2-style positioning is therefore closer to:

```text
design knowledge base
+ reasoning rules
+ search
+ design-system generator
+ agent Skill
```

than to a simple static prompt pack.

## 2. Relationship to existing AI-Harness UI research

Relevant existing record:

- `incubator/proposals/2026-10-15-ui-design-skill-component-comparison-prep.md`

Existing environment also has or has tested external frontend-agent Skills.

The key question is not whether UI UX Pro Max is "good."

It is whether it adds measurable value beyond:

- current model capability,
- existing frontend Skills,
- existing project-specific design rules,
- MagicPath / other design tooling,
- static DESIGN.md-style references.

## 3. Why the reassessment improves its standing

Earlier overlap concern remains valid, but the current project has stronger differentiation through:

- searchable structured design data,
- industry-specific rules,
- explicit anti-pattern guidance,
- automatic design-system generation,
- broad framework coverage.

That makes it reasonable to compare rather than dismiss as duplicate.

## 4. Important boundary: Basic vs Premium

The official repository distinguishes:

- open-source Basic repository
- Premium commercial capabilities

Premium features include broader brand and asset-generation functionality.

Do not attribute Premium features to the open-source repository during evaluation.

Any comparison must use the exact open-source version unless Human separately approves paid tooling.

## 5. Risks

- another large Skill can conflict with existing project style
- design recommendations can become generic or over-prescriptive
- search/rules do not prove visual quality
- more guidance can increase token/context load
- automatic style generation can override Human-approved aesthetics if used carelessly
- installation across many agent directories can create duplication
- current repository metrics/features can change quickly

## 6. Best comparison

Use one real UI task.

```text
A: current frontend Skills / baseline
B: UI UX Pro Max only
```

Keep constant:

- model
- prompt
- source commit
- target screen
- functional requirements
- accessibility requirements
- time budget

Measure:

- Human visual preference
- information hierarchy
- usability
- responsive behavior
- accessibility
- regressions
- dependencies
- token/time cost
- amount of Human correction

Do not combine multiple new design Skills in the first comparison.

## 7. Relationship to Local AI Soul

UI UX Pro Max should not automatically redesign the frozen Local AI Soul V0.1.

That project already has a frozen visual direction and external Orb choice.

A later comparison may use a non-frozen screen or a future UI iteration, but V0.1 should not be destabilized to test this Skill.

## Decision

**A+ / COMPARISON CANDIDATE / IMPLEMENTATION HOLD**

The previous "mostly duplicate" interpretation should be softened.

Current evidence supports a controlled comparison against existing frontend Skills, not immediate replacement or installation.

No Skill installation, project-wide style change, paid upgrade, or product redesign is authorized by this record.
