# GROWgle — Coverage Gap Priority Checkpoint

Date: 2026-10-21
State: CURRENT
Purpose: Second Pass research-order pivot

## Decision

Use the current state as a rollback / restart point.

From this checkpoint, regional Second Pass priority changes from mostly sequential continuation to:

`ZERO / THIN REGION -> RECOVERY PASS -> MATURITY REASSESSMENT`

This does not discard prior work or change the research depth rules.

## Why

Hayashima demonstrated that a low/zero dashboard count can represent a research-route failure rather than a true lack of opportunities.

Before targeted recovery:
`HAYASHIMA = 0 / effectively empty in dashboard`

After targeted source-by-source Second Pass:
- recurring child programs
- public events
- library / children's center activities
- youth volunteer growth route
- local heritage activity
- school / digital inclusion activity
- regional sports-system source

Therefore zero / thin counts are now treated as a possible coverage warning.

## Compatibility with existing rules

This pivot is compatible with current GROWgle rules:

- V1 geographic expansion is already complete for the 12-prefecture scope.
- Second Pass is a depth phase, not a fixed geographic sequence.
- Existing calibration says to prioritize underexplored layers.
- Stop rule remains based on new SOURCE / SYSTEM / GROWTH_ROUTE yield.

The older broad-search regional order remains historical First Pass guidance, not a mandatory Second Pass queue.

## New Second Pass priority

Priority 1 — ZERO regions
- no public-list candidate
- no structured SOURCE
- or dashboard shows effectively zero

Priority 2 — THIN regions
- only 1–2 isolated events
- no SYSTEM SOURCE
- no recurring SOURCE
- no growth route
- major category / age gaps

Priority 3 — UNEVEN regions
- some strong categories but obvious geographic / age / access gaps

Priority 4 — already strong / near-saturated regions
- revisit only for current updates, WATCH resolution or a new Gateway

## Recovery-pass method

For each ZERO / THIN region:

1. Existing-log audit
   - distinguish truly unsearched from searched-but-unresolved
2. Municipality official
3. Board of education / lifelong learning
4. Public hall / library / youth / children's center
5. Afterschool / school-community collaboration
6. Social welfare council / volunteer routes
7. School / high school / university / kosen provider activity
8. NPO / local organization / chamber / company
9. current OPEN_PUBLIC activity check
10. SYSTEM SOURCE / YOUTH ACTION / GROWTH_ROUTE check

Then set one of:
- RECOVERED_NOT_EMPTY
- STILL_THIN
- SATURATED_FOR_SECOND_PASS
- NEEDS_SPECIAL_ROUTE

## Ranking principle

Do not rank only by raw event count.

Use:
- public participation availability
- source diversity
- recurring/system source presence
- age coverage
- growth route presence
- regional distinctiveness
- information-source fragmentation
- confidence that the area was actually searched deeply

## Guardrails

Do not:
- restart all regions from zero
- over-collect every small event
- penalize small municipalities for low population
- assume zero means no opportunities
- abandon current regional meaning / SOURCE-ACTIVITY separation

Do:
- use the current GitHub corpus as baseline
- prioritize coverage gaps
- preserve all prior saturation judgments
- stop a recovery pass when new-source yield flattens
