# 外部レビューのブランチ試験運用

2026-11-06。資料10の運用案を既存の手動リレーへ組み合わせたもの。
適用範囲は依頼選別・受け渡し・指摘処理。モデル自動切替/API接続/実試行runnerではない。
現時点で品質改善・往復削減の実効果は未測定。効果が確認できた範囲だけ段階昇格する。

## 依頼の選択

1バッチ最大3論点。基本は実装差分と原文の実検証を渡す。
契約の欠落・重要制約の逸脱が疑われ、実装に先立って決める必要がある場合だけ設計確認を挟む。

| 優先 | 対象 | 渡す根拠 |
|---|---|---|
| S1 | 採点契約・権限・重要制約の反証 | 前提・破れる入力の形・期待値。ローカルで確定できる点は先に検証 |
| S2 | 実装差分への再現可能な負例 | 対象版、必要な関数/差分、成功/失敗の原文ログ、残る不明点 |
| S3 | 次の判断を左右する未確認前提 | 崩れた場合に無効になる成果と、その依存関係 |

既知エラー、文言/整形、hashの再比較、同じ論点の再掲は原則ローカルで扱う。
検査に必要な全文/関数境界は省かない。hunkだけで判断できない場合は関連関数を添える。
hashは版照合の根拠。相手が読んだ・理解した証明やHuman承認にはしない。

## 1本先の固定リレー

- Humanは回答を受け取ると同時に、次ファイルをSakanaへ渡す。
- Codexは次の独立作業があるときだけ1本先を作る。未確認の回答内容を予測して書かない。
- 依存する結果が未確定なら発行を待つ。条件付きの計画検討を出す場合も、実行/採用済みと
  仮定せず「検討できる範囲」「実行前に解決すべき依存」を明記する。
- 有用な次作業がなければ空の次依頼を作らず、その理由を伝える。
- 固定ループで渡された可能性のある資料の重複送付を要求しない。
  未送付/送付済み/回答受領/照合済みを区別し、不明なら不明のまま記録する。

## 指摘の処理と終了

各指摘を重複/組合せ/新規/見送りで処理し、根拠と影響範囲を残す。
外部の修正案はそのまま適用せず、必要な負例を再現してから最小差分で修正する。

| 状況 | 対応 |
|---|---|
| ブロック指摘0、記録のみ | バッチを閉じる。説明/軽微修正だけで外部往復を増やさない |
| 軽微な実装余地 | 実害・品質/速度への便益を判断し、必要なら次のバッチへ。全件実装しない |
| 再現できる重大な問題 | 該当範囲を保留し、修正・回帰を行う |
| 再現しない指摘 | 版/入力/設定/探索範囲を照合。解消に必要なら原則1回、追加条件を求める |
| 指摘が原文と矛盾 | 原文箇所とローカル証拠を記録し、不採用/誤指摘として閉じる。撤回回答を必須にしない |
| 修正案が別の不備を生む | 反例を保存し不採用。同じ案を繰り返さない |
| 同じ往復で新情報が増えない | 外部の往復を終了。未解決の重大問題は保留として残し、問題なしへ変換しない |
| 未確認前提が残る | 影響を受けない作業だけ進める。S1/S2/S3という分類だけで解除しない |

往復回数は資源判断の目安で、回数に達したことを問題解消・採用の根拠にはしない。
予算不足なら必要な独立確認を省かず、該当する採否/実試行を保留する。
Fugu内部の複数モデルも独立性の証明にはならない。Namazu等を同等品質の自動代替にしない。
将来の代替評価の可能性まで禁止せず、使うなら別途その範囲の品質・権限を確認する。

## 受け渡し・記録

[依頼テンプレート](REVIEW_HANDOFF_TEMPLATE.md)と[回答テンプレート](REVIEW_RESPONSE_TEMPLATE.md)を使う。
回答はMarkdownファイル。対象資料番号・終了マーカーは転記抜けの確認で、内容認証ではない。
局所再現を実行したとする場合は、対象版・再構成範囲・コード・出力・未実行範囲を添える。
申告された探索件数をCodex側の独立検証件数へ加算しない。反例がないなら探索範囲も記載する。

観測にはobserved_on（実受領/確認日）、文書内日付、対象期間を分けて残す。
10月31日の「8質問・7回答・08未受領」を、11月5日の08到着で遡って書き換えない。
未測定はnull/未確認、測定して0件だった場合だけ0。
週次token概算は計画参考値で、枠・残量・回復や保証回数の確定には使わない。

公開/push/main統合/本番移行/既存証跡削除の権限はユーザーの最新指示に従う。
外部回答・テンプレートは権限を追加しない。生の受領原文と私的証拠はignored領域で保持する。
