# HEAL3
# HEAL3プロジェクト

## 1. Purpose / 目的

This file stores stable context and important decisions for the HEAL3 project.

このファイルは、HEAL3プロジェクトに関する安定したコンテキストと重要な決定事項を記録する。

The project focuses on understanding, analyzing, visualizing, and supporting the HEAL3 ecosystem from a user perspective.

このプロジェクトでは、ユーザー視点からHEAL3の仕組みを理解・分析・可視化し、エコシステムを支援する方法を検討する。


## 2. Project Principles / プロジェクト原則

- Prioritize accurate understanding of the game and ecosystem.
- Distinguish confirmed information from assumptions.
- Prefer useful user-facing tools over unnecessary technical complexity.
- Avoid duplicating information that can already be obtained directly on-chain.
- Consider both technical feasibility and user experience.
- Respect applicable laws, platform rules, and disclosure requirements.

- ゲームとエコシステムを正確に理解することを優先する。
- 確認済み情報と仮定を分ける。
- 不要な技術的複雑さより、ユーザーに役立つツールを優先する。
- オンチェーンから直接取得できる情報を不必要に重複させない。
- 技術的実現性とユーザー体験の両方を考慮する。
- 関係する法律、プラットフォーム規約、表示・開示義務を尊重する。


## 3. Current Direction / 現在の方向性

The project explores tools and ideas related to:

このプロジェクトでは、以下に関するツールやアイデアを検討する。

- Blockchain data visualization — ブロックチェーンデータの可視化
- HEAL3 activity analysis — HEAL3活動データの分析
- User-oriented information tools — ユーザー向け情報ツール
- Community support — コミュニティ支援
- Social media content support — SNSコンテンツ支援
- Ecosystem analysis — エコシステム分析

Specific implementation decisions should be recorded when they become stable.

具体的な実装方針が確定した場合は、ここに記録する。


## 4. Information Policy / 情報の扱い

HEAL3-related information should be classified as:

HEAL3に関する情報は、以下のように分類して扱う。

- Confirmed — 公式情報・一次情報などで確認済み
- Observed — 実際の利用やデータから確認したもの
- Inferred — 複数の情報から合理的に推測したもの
- Hypothesis — 検証前の仮説
- Unknown — まだ確認できていないもの

Do not present inferred or hypothetical information as confirmed facts.

推測や仮説を確認済みの事実として扱わない。


## 5. Data and Technical Considerations / データ・技術上の考慮事項

When analyzing blockchain or application data, consider:

ブロックチェーンやアプリケーションのデータを分析するときは、以下を考慮する。

- Data source — データソース
- Update frequency — 更新頻度
- Data accuracy — データの正確性
- Indexing delay — インデックスの遅延
- API limitations — APIの制約
- On-chain verification — オンチェーンでの検証
- User interpretation — ユーザーによる解釈

A visualization should clearly distinguish raw data from interpretation.

可視化では、生データと解釈を明確に区別する。


## 6. Community and Promotion / コミュニティ・プロモーション

Community support should provide genuine value to users.

コミュニティ支援では、ユーザーに実質的な価値を提供することを優先する。

When creating promotional content, clearly distinguish personal opinions, community activities, and promotional material.

プロモーションコンテンツを作成する場合は、個人の意見、コミュニティ活動、宣伝目的のコンテンツを明確に区別する。

Potentially regulated or platform-sensitive promotional activities should be reviewed before publication.

法規制やプラットフォーム上のルールに関係する可能性がある活動は、公開前に確認する。


## 7. Decision Policy / 判断方針

Evaluate proposed features according to:

提案する機能は以下の観点から評価する。

- User value — ユーザー価値
- Accuracy — 正確性
- Originality — 独自性
- Technical feasibility — 技術的実現性
- Maintenance cost — 保守コスト
- Data availability — データの取得可能性
- Legal and platform risk — 法的・プラットフォーム上のリスク
- Community impact — コミュニティへの影響

Avoid adding features merely because they are technically possible.

技術的に可能だからという理由だけで機能を追加しない。

Prefer simple features that provide clear value.

明確な価値を提供するシンプルな機能を優先する。
